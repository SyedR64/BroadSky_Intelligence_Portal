# Contract — portfolio website concepts and software ("OS") pages

Everything here ships as static files (no build step). The shell they sit beside is Broad Sky OS (`UNIFIED.md`, `README.md`). Pages live at:
- `index.html` — the front door: a forwarding page into `app.html#/home/overview` (the firm view of Broad Sky OS). The shell is `app.html` (screens at `app.html#/<module>/<screen>`).
- `redesigns/index.html` — gallery of the six portfolio website concepts + the OS program.
- `redesigns/<slug>/index.html` — one concept site per company: `punctual-pros`, `cet`, `frontline`, `thomas-scientific`, `bpi`, `fair-harbor`.
- `redesigns/<slug>/<os>.html` — the company's software page + interactive demo (shown in the shell as the company's **Tools** screen, `#/<co>/tools`): `serviceos.html` (PP), `gridos.html` (CET), `firmos.html` (FL), `labos.html` (TS), `signalos.html` (BPI), `harboros.html` (FH).
- `redesigns/<slug>/growth-plan.html` (Punctual Pros: `nationwide.html`) — the company's growth plan (shown in the shell as **Plan**, `#/<co>/plan`).
- `modules/techos.js` — shell module "Tech enablement" (group Intelligence) summarizing all six OS theses with valuation math.

## Shared assets you MUST use
- Fonts: Google Fonts Inter (400–800) + JetBrains Mono. Icons: inline SVG only (no icon fonts).
- Chat widget: `import { Chat } from '../../assets/chat.js?v=VERSION';` (from `redesigns/<slug>/`; use `../assets/chat.js` from `redesigns/`, `./assets/chat.js` from root). Then
  `Chat.mount(null, { persona: '<pp|cet|fl|ts|bpi|fh>', mode: 'floating', theme: 'light', faq: [{q, a (HTML), href?}], suggestions: [...] })`.
  The widget already knows real data: PP zip coverage (`Do you serve 17601?`), live NWS storms, CET programs. Add 8–15 site-specific FAQ entries (services, pricing model, hours, coverage, careers, OS product) so the fallback is useful. The launcher reads "Ask" + the persona's short name; inside the shell the assistant is "Broad Sky OS" and its launcher reads "Ask" (`UNIFIED.md` §5). Never use the earlier product name or its shorthand in any FAQ, greeting or suggestion.
- Data: `import { Data, Fmt, Live } from '../../assets/core.js?v=VERSION'` gives the same loaders as the shell (`Data.load('pp_zips')`, `Data.research('cet_opportunities')`, `Live.nwsAlerts('PA')`, `Live.forecast(lat, lon)`). Use REAL data for site widgets (coverage maps, live storm banner, bid radars, account-health demos) — it is what makes these concepts credible.
- Maps: Leaflet 1.9.4 from unpkg with the Esri tiles exactly as `assets/core.js` `Maps.create` does (copy the tile URLs; dark or light canvas).
- Images: NO external raster images and NO copyrighted logos. Build visuals with CSS gradients, patterns, inline SVG illustrations/icons, device mockups that embed the portal screenshots in `assets/img/` (listed in `assets/img/README.md` when present), and data-driven visuals (maps, charts). Never name brands as design inspiration; describe the principle instead.

## Concept-site requirements (each `redesigns/<slug>/index.html`)
1. Concept notice: the frame draws it (`Frame.BANNER_TEXT`, "A concept by Syed Rahman for Broad Sky Partners (BSP), not the company's official website.") as the concept tag in the page bar, with the crumb `Concepts / ● Company`. A page never writes its own notice. The top bar, the "Viewing as" switch and the footer come from `Frame.mount({})` too.
2. Modern, conversion-oriented marketing site with a distinct design system per company (write it in `redesigns/<slug>/site.css`; prefix nothing — each site is standalone): nav, hero with primary CTA, trust/social proof, services/products, a data-powered section (see below), the OS product teaser, testimonials or case studies (clearly labelled "illustrative" if not sourced), FAQ, contact/CTA, footer. Fully responsive (390px → 1440px), accessible (landmarks, alt text, focus states), fast (no frameworks; <400 KB page weight excluding data).
3. A "Design rationale" drawer/section: the 2–3 design principles the system applies (from `data/research/design_refs.json` when present, stated as principles such as "Lead with the number" or "Controls up front", never as the names of the sites or companies they came from), what each element does for conversion or valuation, and the KPIs it should move. This is for the Portfolio Resource Group, so make it sharp and specific.
4. Data-powered section per company: PP = live "storm readiness" banner (NWS) + zip coverage checker + membership calculator; CET = capabilities map of the states it is licensed in (HQ Worcester MA; Taunton, Norwell and Horton CT as sites) + open programs. CET text follows `UNIFIED.md` §0: no New York City plan, and "New England only" is not correct; FL = security-posture self-assessment + outcome stats; TS = product category finder + account-rep match (by state); BPI = "narrative monitor" style demo with illustrative data; FH = fit finder + sustainability counter (bottles recycled, illustrative formula stated).
5. Chat widget mounted with the persona + FAQ (see above) and 4–6 suggestions that match the site.
6. Software page link in nav and hero (e.g., "Powered by ServiceOS").
7. Embedded form: with `?embed=1` the page draws no bar, footer, crumb, concept tag, page sub-bar or floating Ask button, fills the shell's content area with one scroll, and every link that leads to `app.html` or another page opens in the top window (`UNIFIED.md` §9a). The shell shows it as Tools or Plan.

## OS product pages (`redesigns/<slug>/<os>.html`)
Think "a product page that puts the KPIs before the prose, meets a PE value-creation memo". Sections: hero (name, one-line promise, 3 KPIs it moves); what it is (5–7 modules with icons); interactive demo (a working mock UI driven by real portal data where possible — ServiceOS: dispatch board + capacity index from `pp_demand_model` and `Live.forecast`; GridOS: bid board from `cet_opportunities` + solar fleet monitor; FirmOS: security score + service desk deflection calculator; LabOS: account-health from `ts_parents`; SignalOS: narrative monitor; HarborOS: fit/size + replenishment + wholesale portal); the value-creation math (investment, timing, EBITDA impact range, multiple-expansion case using `data/research/serviceos_evidence.json` and `public_comps` — every number labelled est. with the source); build-vs-buy stack (named vendors from the evidence file); 12-month roadmap; risks; "why a buyer pays for this at exit". Footer links to the shell screen `app.html#/techos/overview`.

## Shell module `modules/techos.js`
Follow `CONTRACT.md` (module API). Views: `overview` (six OS cards with the thesis, KPIs moved, est. EBITDA impact, est. investment, time-to-value, evidence links, link to each OS page), `evidence` (the valuation-premium evidence table from `serviceos_evidence.json` with sources and confidence, public comps tie-in), `roadmap` (Gantt-like 12–24 month plan across companies, PRG owner, dependencies), `calculator` (EBITDA uplift × multiple expansion → equity value created; inputs with sliders; defaults from the evidence file; labelled assumptions). Tour steps: 3–4.

## Front door
`index.html` holds no content of its own: it forwards into `app.html#/home/overview` and maps the old front-page anchors (`UNIFIED.md` §9). The shell's top bar has Home, Agent, Connections and Concepts on standalone pages; the two films and the memo sit on the Narrated tour screen (`app.html#/briefing/play`).
