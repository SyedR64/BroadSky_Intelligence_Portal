# Contract — portfolio website concepts, landing page, and "OS" product pages

Everything here ships as static files on GitHub Pages (no build step). Pages live at:
- `index.html` — public landing for **Broad Sky Operating Intelligence** (NYC-startup look, chat front and center). The intelligence app lives at `app.html` (hash routes `app.html#/<module>/<view>`).
- `redesigns/index.html` — gallery of the six portfolio website concepts + the OS program.
- `redesigns/<slug>/index.html` — one concept site per company: `punctual-pros`, `cet`, `frontline`, `thomas-scientific`, `bpi`, `fair-harbor`.
- `redesigns/<slug>/<os>.html` — the company's "OS" product page + interactive demo: `serviceos.html` (PP), `gridos.html` (CET), `firmos.html` (FL), `labos.html` (TS), `signalos.html` (BPI), `harboros.html` (FH).
- `modules/techos.js` — portal module "Tech enablement" (group Intelligence) summarizing all six OS theses with valuation math.

## Shared assets you MUST use
- Fonts: Google Fonts Inter (400–800) + JetBrains Mono. Icons: inline SVG only (no icon fonts).
- Chat widget: `import { Chat } from '../../assets/chat.js?v=VERSION';` (from `redesigns/<slug>/`; use `../assets/chat.js` from `redesigns/`, `./assets/chat.js` from root). Then
  `Chat.mount(null, { persona: '<pp|cet|fl|ts|bpi|fh>', mode: 'floating', theme: 'light', faq: [{q, a (HTML), href?}], suggestions: [...] })`.
  The widget already knows real data: PP zip coverage (`Do you serve 17601?`), live NWS storms, CET programs. Add 8–15 site-specific FAQ entries (services, pricing model, hours, coverage, careers, OS product) so the fallback is useful. On the landing page use `mode: 'inline'` inside the hero: `Chat.mount(document.querySelector('#hero-chat'), { persona: 'portal', mode: 'inline', theme: 'light' })` — autocomplete, suggestion chips and the thread are built in.
- Data: `import { Data, Fmt, Live } from '../../assets/core.js?v=VERSION'` gives the same loaders as the portal (`Data.load('pp_zips')`, `Data.research('cet_opportunities')`, `Live.nwsAlerts('PA')`, `Live.forecast(lat, lon)`). Use REAL data for site widgets (coverage maps, live storm banner, bid radars, account-health demos) — it is what makes these concepts credible.
- Maps: Leaflet 1.9.4 from unpkg with the Esri tiles exactly as `assets/core.js` `Maps.create` does (copy the tile URLs; dark or light canvas).
- Images: NO external raster images and NO copyrighted logos. Build visuals with CSS gradients, patterns, inline SVG illustrations/icons, device mockups that embed the portal screenshots in `assets/img/` (listed in `assets/img/README.md` when present), and data-driven visuals (maps, charts). Never name brands as design inspiration; describe the principle instead.

## OS product pages (`redesigns/<slug>/<os>.html`)
Think "a product page that puts the KPIs before the prose, meets a PE value-creation memo". Sections: hero (name, one-line promise, 3 KPIs it moves); what it is (5–7 modules with icons); interactive demo (a working mock UI driven by real portal data where possible — ServiceOS: dispatch board + capacity index from `pp_demand_model` and `Live.forecast`; GridOS: bid board from `cet_opportunities` + solar fleet monitor; FirmOS: security score + service desk deflection calculator; LabOS: account-health from `ts_parents`; SignalOS: narrative monitor; HarborOS: fit/size + replenishment + wholesale portal); the value-creation math (investment, timing, EBITDA impact range, multiple-expansion case using `data/research/serviceos_evidence.json` and `public_comps` — every number labelled est. with the source); build-vs-buy stack (named vendors from the evidence file); 12-month roadmap; risks; "why a buyer pays for this at exit". Footer links to the portal view `app.html#/techos/overview`.

## Portal module `modules/techos.js`
Follow `CONTRACT.md` (module API). Views: `overview` (six OS cards with the thesis, KPIs moved, est. EBITDA impact, est. investment, time-to-value, evidence links, link to each OS page), `evidence` (the valuation-premium evidence table from `serviceos_evidence.json` with sources and confidence, public comps tie-in), `roadmap` (Gantt-like 12–24 month plan across companies, PRG owner, dependencies), `calculator` (EBITDA uplift × multiple expansion → equity value created; inputs with sliders; defaults from the evidence file; labelled assumptions). Tour steps: 3–4.

## Landing page (`index.html`, `assets/landing.css`, `assets/landing.js`)
Modern startup aesthetic (white/off-white, large tight headlines, one gradient accent, pill buttons, generous spacing, crisp cards, subtle motion on scroll). Structure: nav (Portal, Site concepts, OS program, Briefing, GitHub); hero: "Hello, Broad Sky." / "Whatever you need from the portfolio, start here." with the inline chat (america.gov-style prompt box, voice button, suggestion chips); a "what it answers" strip (6 example prompts that route into modules); product tour (3–4 screenshots from `assets/img/` in device frames with captions); numbers strip (datasets, home sales, opportunities, targets, sponsors — computed at load from `data/manifest.json` + research files, with graceful fallback); the six companies grid (each card links to its portal module and its concept site); the OS program section (six cards); the briefing video section (embed `briefing/broad_sky_briefing.mp4` with poster); "built for the Portfolio Resource Group" footer with disclaimer. Must load in < 1.5 s on broadband without the data (lazy-load numbers), and must be beautiful at 390px.
